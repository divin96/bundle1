The key is always a string or a Symbol. The value can be any valid JS data type. 2. **Dot vs Bracket notation:** Dot notation (`obj.key`) requires the key to be a valid JS identifier (no spaces, can't start with numbers, etc.) and evaluates literally. Bracket notation (`obj["key"]` or `obj[myVar]`) evaluates the expression inside the brackets to a string, allowing spaces, numbers, and dynamic variables. 3. **Array Type:** Arrays are not distinct primitive types. Under the hood, `typeof []` returns `"object"`. They are exotic objects tailored with special behaviors, like automatic `.length` management and an optimized prototype chain (`Array.prototype`). 4. **`for...in` vs `for...of`:** `for...in` iterates over the *enumerable property keys* of an object (including inherited ones). `for...of` iterates over the *values* of an iterable object (like Arrays, Strings, Maps). Never use `for...in` for arrays because it iterates over string keys and includes inherited array prototype properties. 5. **`break` vs `continue`:** `break` immediately terminates the loop completely. Execution resumes at the first statement after the loop block. `continue` skips the rest of the *current* iteration and jumps straight to the next iteration's condition check. 6. **`if/else` vs `switch`:** `if/else` evaluates boolean expressions for each condition. `switch` evaluates a single expression once, and uses strict equality (`===`) to match it against multiple `case` clauses. `switch` can be more readable for multiple exact matches, but they serve similar structural purposes. ### Intermediate Theory Questions 1. **Property Descriptors:** Every property has hidden attributes. - `enumerable`: If true, it shows up in `for...in` loops and `Object.keys()`. - `writable`: If true, the value can be changed via assignment. - `configurable`: If true, the property can be deleted, and its descriptor attributes can be modified. 2. **Array Indices:** Internally, standard JS array indices are coerced to Strings. `arr[1]` is conceptually identical to `arr["1"]`. The engine recognizes string keys that represent 32-bit positive integers and handles them efficiently, but structurally, it's still an object property key. 3. **Sparse Arrays:** If you assign `arr[100] = 2`, the engine does not physically allocate 100 memory slots. It creates an object-like mapping with a key of `"100"` and a value of `2`. The `length` property automatically updates to the highest integer index + 1 (returning 101). Indices 0-99 are "empty slots" (not even initialized to `undefined`, they just don't exist). 4. **Functional Iteration:** Standard `for` loops are imperative; you dictate exactly *how* to iterate, often mutating external variables (side effects). `map`, `filter`, and `reduce` are declarative. They do not mutate the original array (pure functions) but return a entirely new array or value, adhering to functional programming principles. 5. **Property Order:** Historically, property order was not guaranteed. In ES6, iteration order for objects is strictly defined: Integer keys (in ascending numeric order) first, then string keys (in insertion order), then Symbol keys (in insertion order). 6. **`label` Statement:** It acts as an identifier for a loop. You use it in conjunction with `break` or `continue` to escape or skip from deeply nested loops. Without a label, `break` only terminates the immediate inner loop. ### Advanced Theory Questions 1. **Dictionary vs Hidden Classes:** JS engines like V8 try to optimize objects by creating internal C++ structs called "Hidden Classes" (or Shapes). If you create `{x: 1, y: 2}`, it creates a shape predicting memory offsets. If you suddenly do `delete obj.x` or add a new property, the object's structure changes. V8 drops the fast Hidden Class optimization and degrades the object to a slower "Dictionary Mode" (a hash table), significantly degrading read/write speeds. 2. **Typed Arrays:** Standard arrays are dynamic, hash-table-like objects that can store mixed types. Typed Arrays (e.g., `Int32Array`) allocate a contiguous, fixed block of raw binary memory buffer (`ArrayBuffer`). They can only store a specific numeric type, making them lightning-fast and memory-efficient, mimicking arrays in lower-level languages like C. 3. **Array Reallocation:** When an array runs out of its initial allocated contiguous memory space, the engine must pause, allocate a new, larger block of contiguous memory (often 1.5x or 2x the old size), copy all existing elements to the new block, and then garbage collect the old block. This is a computationally expensive operation. 4. **`finally` Precedence:** The `finally` block ALWAYS executes, regardless of what happens in `try` or `catch`. If the `finally` block contains a `return` statement, it completely overrides any `return` statement that was pending execution from the `try` or `catch` blocks. 5. **Object `for...of`:** Standard objects are not Iterable. They lack the `[Symbol.iterator]` property. To make an object work with `for...of`, you must add a method named `[Symbol.iterator]` that returns an iterator object (which must have a `next()` method returning `{ value: any, done: boolean }`). ### Predict the Output Explanations **Snippet 1:** - Output: `"c"`, `1`. - **Reasoning:** In JS objects, all property keys are ultimately strings. `"1"`, `1`, and `[1]` (computed property evaluating to `1`) all resolve to the exact same string key `"1"`. The assignments simply overwrite each other. The object ends up with a single key `"1"` holding the value `"c"`. **Snippet 2:** - Output: `undefined`, `undefined`. - **Reasoning:** Truncating an array's `length` property physically deletes elements beyond that length. `arr.length = 0` clears the array, so `arr[0]` is undefined. This `return 3` overrides the pending `return 1` and the function exits. ### Debugging Challenges Explanations **Challenge 1:** - **Bug:** `queue.length` only tracks integer indices. - **Why:** `queue["fast"] = "Task 4"` adds a string property to the underlying array object, but it is not a valid numeric index. The `length` property specifically tracks the highest numeric index + 1. The highest index is `2` (from `"2"`), so length is `3`. The `"fast"` property is there, but doesn't affect length. **Challenge 2:** - **Bug:** Modifying the array's length while iterating forward causes indices to shift. - **Why:** When `i=2`, `numbers[2]` is `3`. It gets spliced. The array becomes `[1, 2, 4, 5]`. The element `4` shifts from index 3 to index 2. The loop increments `i` to `3`. The loop then checks `numbers[3]`, which is now `5`. The element `4` was skipped entirely. - **Fix:** Either iterate backwards (`for (let i = arr.length - 1; i >= 0; i--)`), or decrement `i` after splicing (`numbers.splice(i, 1); i--;`). ### Explain the Internal Behavior Explanations 1. **Object Freezing Internals:** When `Object.freeze()` is called, the JS engine iterates over every property and modifies their Property Descriptors. It sets `configurable: false` (preventing deletion/descriptor changes) and `writable: false` (preventing value reassignment). Finally, it flags the object's internal `[[Extensible]]` slot to `false` (preventing addition of new properties). 2. **`for...of` Protocol Trace:** - The engine checks if the object has a method at `obj[Symbol.iterator]`. - It calls this method, which returns an Iterator object. - The engine enters a hidden `while` loop. - It calls `iterator.next()`. - The method returns an object like `{ value: 10, done: false }`. - The engine extracts `value` and assigns it to the loop variable. - The loop body executes. - It repeats until `next()` returns `{ done: true }`, at which point the loop terminates. ### Trick Questions and Edge Cases Explanations **Edge Case 1:** - Output: `"Second"` - **Reasoning:** You cannot use an object as a property key directly. JS implicitly calls `.toString()` on the key. `obj1.toString()` evaluates to the string `"[object Object]"`. `obj2.toString()` also evaluates to `"[object Object]"`. The second assignment simply overwrites the first. `mainObj["[object Object]"]` becomes `"Second"`. **Edge Case 2:** - Output: `3`, `undefined`. - **Reasoning:** The `delete` operator removes the property from the object, but it does NOT shift array elements or change the `length`. It simply leaves an "empty slot" at index 1. Accessing that empty slot returns `undefined`.
